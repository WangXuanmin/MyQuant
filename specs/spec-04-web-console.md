# Spec 04：本地量化交易辅助网页

## 1. 目标与已确认边界

把已有 Python 模拟账户、行情缓存、交易引擎与回测指标接入本地网页，方便查看和手动操作。用户已确认仅在本机运行，并允许按钮更新本地模拟账户。

本章新增操作界面，继续使用已有策略与执行口径。访问页面、刷新页面和查看行情不会触发模拟结算。所有任务由用户点击“开始执行”提交；不设置后台定时任务。

- 服务绑定 `127.0.0.1`；默认端口 `8765`。
- 境内 ETF、沪深 A 股主板；沿用排除创业板、科创板和北交所等规则。
- 原模拟账户与历史保留；不会重置 50 万资金，不恢复已取消的 5 笔旧草稿。
- 净佣万 0.85 免五，其他费用独立计提；ETF 滑点 5 bps，A 股 10 bps。
- 15% 回撤仅提示，继续模拟成交；停牌、涨跌停、现金与可卖数量等规则仍执行。
- 未成交意图最多保留 3 个交易日，每日重新风控。
- 使用新浪原始日线；暂不处理公司行动。
- 不接券商，不提供真实下单、充值、重置账户或清空账本的按钮。

## 2. 为什么这样组织

日常交易辅助需要同时看资金、信号、交易条件与执行记录。单独显示收益图会遗漏数据时点、费用和未成交原因，也容易把旧策略回测当成当前账户表现。

参考 [QuantConnect 官方回测结果文档](https://www.quantconnect.com/docs/v2/cloud-platform/backtesting/results)中图表、指标、订单事件和日志共同呈现的组织方式，设计六个页面。页面布局、代码和图表自行实现，不使用第三方网站图片或登录账户。

轻量 HTTP 服务与浏览器原生 JavaScript 足以满足单机使用。接口调用现有 `DailyRunner`、`ResearchBacktestRunner` 与 SQLite 账本，不另写成交算法。页面资源全部本地提供，不依赖 CDN。

## 3. 页面与输入输出

| 页面 | 内容 | 可执行操作 |
| --- | --- | --- |
| 账户概览 | 总资产、现金、有效净值、回撤、调仓计划、行情新鲜度、真实前向进度 | 更新行情、每日模拟 |
| 候选与行情 | 候选排名、资产过滤、名称/代码搜索、原始 K 线、成交量、MA5/MA20、报告时点因子 | 查看缓存证券、更新行情 |
| 组合与订单 | 当前持仓、批次可卖数量、固定股数订单、有效期、订单/配置/回撤事件 | 开盘状态采集、每日模拟 |
| 研究与回测 | 独立研究记录、已有封装指标、净值、数据覆盖和研究限制 | 新建回测、导出结果 |
| 运行记录 | 原始日报、分析修订、旧版归档、持久任务状态、工程验收 | 查看/重建日报、分析修订、更新日历 |
| 策略配置 | 资产范围、名单、流动性门槛、调仓间隔、排名缓冲、因子/组件权重、仓位上限 | 校验、保存配置 |

日常模拟输入：交易日期、`sh/sz` 代码列表、是否离线。日期限制继续由原引擎校验。非交易日的“每日模拟”按钮禁用；历史分析通过已提交日期的分析修订入口进行。

回测输入：起止日期、证券列表、可选参考基准、是否离线。基准须在本次证券列表内。使用独立研究账户，输出指标、净值、覆盖说明与文件；不修改日常账户。

操作默认使用现有缓存中的 6 个证券作为明确试运行范围；可在输入框修改，单次最多 100 个证券。配置名单过滤仍由原引擎执行。第一版不提供一键全市场扫描。

配置保存：校验合法类型、有限数值、排名关系和各组权重合计 100%；检查配置哈希，拒绝覆盖较新配置。保存前备份 YAML，生成策略版本与变更记录。保存本身不交易；下一次每日运行由原引擎取消旧配置未成交意图、保留调仓锚点。

## 4. 展示口径

1. 总资产和持仓来自当前账本；有效净值曲线只使用新版有效估值。没有有效序列时显示空状态，累计收益和回撤不编造为零。
2. 旧版候选和回测明确标注日期与口径。旧版回测的费用数值按原文件显示，提示其与当前费率可能不同。
3. K 线来自真实本地新浪缓存，标注最后日期、原始价格及公司行动边界。查看图表不自动联网。
4. 可选基本面/行业数据缺失时显示策略原有降级状态；未实现的 ETF 质量组件如实说明。
5. 工程测试和 12 个实际交易日的前向验证分别显示。工程样本和隔离账户成交不计入真实前向进度。
6. 每项操作在输入窗口说明账户影响。任务状态、结果与错误持久保存；重启后未完成任务显示中断，不能自动恢复或重复下单。已提交结果可从账本查看、重建或幂等重跑。

## 5. 接口与本地运行

只读：`GET /api/state`、`/api/market`、`/api/report`、`/api/jobs` 与报告文件导出。

写操作：`POST /api/jobs`、`POST /api/config`。仅接受本地 Host、同源请求和页面取得的本地令牌；不开放 CORS。任务和配置保存共用单机服务锁，执行中拒绝重复提交和参数修改。端口采用独占绑定，重复启动不能创建第二个监听进程。

服务提供内容安全策略、禁止缓存与 MIME 嗅探；文件导出限制在指定报告目录内。历史 HTML 报告加浏览器沙箱，不执行其脚本。账户提交仍由 SQLite 事务和唯一交易日期保证。

`scripts/Start-Web.cmd` 可双击启动；`Start-Web.ps1` 支持端口与 `-NoBrowser`。启动器检测已有本项目服务，避免重复启动；日志在 `data/web`。`Stop-Web.ps1` 核对记录与实际进程，仅停止本项目网页服务，不删除账户或报告。不要在任务执行中主动停止服务；若发生中断，应先查看账本状态。

第一版不提供多个用户、局域网访问、券商交易和后台自动任务；启动器不配置开机启动。

## 6. 验收标准

| 模块 | 必须通过的检查 |
| --- | --- |
| 只读页面 | GET 不初始化/改写账户；账户值与 SQLite 一致；无数据时正确空态 |
| 候选/图表 | 搜索、资产过滤与代码切换有效；真实 OHLC 日期一致；均线/量能正确渲染 |
| 每日模拟 | 隔离账户经网页提交；同日重跑不增加账本版本；次日股数等于原草稿并计费 |
| 分析/日报 | 分析修订和报告重建不改变账户；概览继续使用已提交报告 |
| 配置 | 错误权重/受保护字段被拒绝；旧哈希冲突；校验不写文件；保存有备份/版本且账户不变 |
| 回测/数据 | 离线更新缓存与独立回测不初始化日常账户；基准/日期输入合法 |
| 状态采集 | 非合格开盘采集显示受阻；复用现有免费 TQ 采集模块；不交易 |
| 任务 | 操作串行；执行中拒绝新任务/改配置；任务可持久查看；重启不自动重试 |
| 本地限制 | 非本地 Host、异源/无令牌写请求与路径越界被拒绝 |
| 文件导出 | JSON/CSV 文件可下载；HTML 使用沙箱；旧报告标识正确 |
| 浏览器 | 六页无未捕获脚本错误；1440、820、390 像素布局可用 |
| 回归 | 原有 94 项加新增 15 项接口测试全部通过；浏览器 11 项流程通过 |

验收脚本 `scripts/accept_web.py` 对真实项目只读操作；写操作仅对 `tests/web/serve_fixture.py` 创建的临时工程账户执行。验收前后真实账户、配置与账本文件哈希须一致。

结果保存于 `runs/acceptance-web-20261002/`。界面验收通过不代表策略已经完成真实前向验证。
