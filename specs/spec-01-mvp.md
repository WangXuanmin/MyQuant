# Spec：量化交易辅助工具 MVP

> 状态：Implemented MVP v0.4  
> 目标目录：`E:\Desktop\quant\project-learning\q10-trading-assistant`  
> 本文将用户明确要求与 MVP 实现选择分开描述。文中的默认参数是工程起点，不代表已经证明最优。

> 2026-09-29 实现说明：证券列表与交易状态、50/50 复合基准、分品种滑点、免费新浪行业趋势/宽度、TdxQuant 基本面接口和综合排名已经实现。TdxQuant 本地服务尚未在本机启用，因此真实财务数据联调仍保持公开降级状态。

## 1. 背景

初阶课程已经覆盖数据获取、信号、组合、风险指标、防过拟合、订单、成交、监控、诊断和因子评估。下一阶段不再以增加 Notebook 为主要目标，而是把这些能力整理成一个可重复运行、可回放、可审计的交易辅助工具。

工具定位为 **人机协作的交易辅助系统**：自动完成数据检查、标的筛选、因子计算、组合建议、风险检查和订单草稿，并在本地模拟空跑账户中记录假设成交、持仓和绩效。MVP 不连接券商或交易终端，也不提交真实资金订单。

## 2. 用户明确要求

1. 选股范围可变。
2. 当前关注：
   - ETF；
   - A 股主板股票；
   - 排除创业板、科创板及其他非主板股票。
3. 后续可以增加新的市场和资产类型。
4. 选股风格为：
   - 量价关系为主导；
   - 个股基本面作为第二层判断；
   - 行业景气度作为环境和加减分依据；
   - 支持资料搜索与证据整理。
5. 其他数据、风险、执行和工程设计按本 spec 的建议实现。
6. MVP 中的 ETF 仅限境内交易所上市 ETF。
7. ETF sleeve 与 A 股 sleeve 的初始目标资金比例约为 1:1，先按 50%/50% 配置。
8. 基本面和行业数据可以评估公开网络来源、同花顺和通达信；如果没有稳定且获授权的来源，先不启用对应因子。
9. 行业分类优先评估主流财经数据平台能够提供的标准及历史版本。
10. 本地模拟账户初始资金为人民币 500,000 元，初始持仓为空。
11. 当前阶段只做本地模拟空跑，不考虑券商或交易终端接入。

本文把用户所写的 “EFT” 按 “ETF” 理解。

## 3. MVP 目标

给定一个运行日期、策略版本和账户快照，系统应能够：

1. 构建当日可交易标的池；
2. 获取并验证当日可见的行情，以及已启用适配器能够提供的基本面和行业数据；
3. 计算量价、基本面、行业景气度三类评分；
4. 生成 ETF 和 A 股主板的候选排名及解释；
5. 根据当前账户生成目标组合；
6. 执行交易前风险检查；
7. 生成可人工审核的订单草稿；
8. 保存完整的输入版本、计算结果、证据和审计记录；
9. 在本地模拟空跑账户中记录订单、假设成交、持仓、现金和绩效；
10. 支持按任意历史日期重放同一次决策。

## 4. 非目标

MVP 暂不包含：

- 任何真实账户交易；
- 分钟级或高频策略；
- 融资融券、做空、期权和期货；
- 使用机器学习直接生成交易决策；
- 未经核验的网页文本直接改变目标仓位；
- 多币种账户的统一资金调度；
- 为追求回测表现而自动反复搜索参数。
- 券商、柜台或交易终端接入。

## 5. 核心原则

### 5.1 时间点正确

所有计算只能使用运行时已经公布的数据。财报、宏观和行业数据必须保存 `published_at`、`effective_at` 和 `fetched_at`。历史回放不得使用后来修订或后来公布的数值。

### 5.2 策略与运行框架分离

稳定框架负责数据、风险、订单、审计和报告；策略插件负责标的池、因子和目标权重。修改策略时创建新版本，不覆盖已经验证或正在模拟运行的版本。

### 5.3 失败时停止生成订单

关键行情过期、复权异常、账户不一致、策略配置为必需的数据缺失或风险检查失败时，运行状态必须为 `BLOCKED`，不得用零值、前值或猜测静默替代。基本面和行业数据在默认配置中属于可选数据；缺失时必须按第 9.5 节公开降级，不能悄悄改变计算口径。

### 5.4 解释和证据优先

每个候选标的必须能回答：为什么入选、使用了哪些数据、数据截止到何时、哪些风险可能使结论失效。

## 6. 系统边界和流程

```text
数据适配器
  → 数据版本与质量检查
  → 动态标的池
  → 量价/基本面/行业因子
  → 候选排名与证据卡
  → 组合构建
  → 交易前风险检查
  → 订单草稿
  → 人工审阅
  → 本地模拟撮合
  → 本地模拟空跑账户
  → 对账、监控和复盘
```

运行频率默认为每个交易日收盘后一次。使用当日收盘数据产生的信号，只能用于下一可交易时点的订单建议。

## 7. 可扩展标的池

### 7.1 统一证券主数据

每个证券至少保存：

| 字段 | 含义 |
|---|---|
| `instrument_id` | 系统内部稳定 ID |
| `symbol` | 数据源或券商代码 |
| `asset_type` | MVP 使用 `CN_ETF`、`CN_A_MAIN`；后续类型通过插件扩展 |
| `exchange` | 交易所 |
| `board` | 主板、创业板、科创板等 |
| `industry_l1/l2` | 行业分类及版本 |
| `list_date/delist_date` | 上市与退市日期 |
| `currency` | 币种 |
| `lot_size/tick_size` | 最小交易单位和价格变动单位 |
| `tradable` | 在指定日期是否可交易 |
| `status` | 正常、ST、停牌、退市整理等 |

不得只依赖代码前缀判断板块；应优先使用带生效日期的交易所或证券主数据字段。代码规则只能作为数据异常时的校验。

### 7.2 初始资产类型

#### ETF

- MVP 仅支持上海、深圳交易所上市的境内 ETF。
- 境外 ETF 不进入 MVP 的 Universe、排名、组合和模拟账户；已有境外数据适配器只能保留为停用的后续研究扩展。
- ETF 需要保存跟踪指数、资产类别、行业主题、规模、成交额、折溢价和分红/拆分信息；缺失的字段在报告中明确标记。

#### A 股主板

- 包含上海和深圳主板；深圳原中小板并入主板后的证券按主数据中的板块属性处理。
- 排除创业板、科创板、北交所、B 股和其他非主板证券。
- MVP 默认排除 ST、`*ST`、退市整理、长期停牌、上市时间不足 120 个交易日和流动性不足的证券。
- 具体排除条件均写入配置并记录命中原因。

### 7.3 动态 Universe 接口

```python
class UniverseProvider:
    def build(self, as_of_date: str, config: UniverseConfig) -> UniverseSnapshot:
        ...
```

`UniverseSnapshot` 必须包含：标的列表、构建日期、纳入/排除原因、数据版本和配置版本。历史回测必须读取当时的快照，避免幸存者偏差。

### 7.4 标的池配置示例

```yaml
universe:
  asset_types: [CN_ETF, CN_A_MAIN]
  exchanges: [SSE, SZSE]
  exclude_boards: [CHINEXT, STAR, BSE]
  exclude_status: [ST, STAR_ST, DELISTING, SUSPENDED_LONG]
  min_listing_days: 120
  min_price: 2.0
  min_median_turnover_20d: 20000000
  custom_include: []
  custom_exclude: []
```

## 8. 数据要求

### 8.1 行情数据

- 日线 OHLCV、成交额、换手率；
- 原始价格与经过核验的复权/总收益价格分开保存；
- 当前按用户决定不处理分红、送股、拆分、配股等公司行为；行情保存为原始价格，报告不得把结果称为总收益；
- 交易日历、停复牌、涨跌停状态；
- 数据源、请求时间、覆盖范围、缺失交易日和校验结果。

行情主源继续使用已经约定的新浪接口。若需要第二数据源做交叉核验，必须显式配置并记录来源，不得静默切换。新浪不能提供的基本面、行业或复权口径应报告缺口，再接入经过批准的数据源。

### 8.2 基本面数据

A 股主板的基本面适配器启用后至少支持：

- 营业收入及同比增长；
- 归母净利润及同比增长；
- ROE；
- 经营现金流/净利润；
- 资产负债率；
- PE、PB、自由现金流收益率中可可靠获得的指标；
- 财报期、公告日、更新日和是否经过审计。

财报因子必须按公告日进入可用集，不得按报告期末日期提前使用。缺失基本面不得填零。

基本面数据源采用免费的 TdxQuant 本地 HTTP 适配器。实现读取 `FN183/FN191/FN197/FN210/FN228/FN232/FN234/FN336`，保留公告日和报告期，并按运行日选择已经公告的最新一条。支持 TQ 的通达信客户端和专业财务数据尚未就绪时，基本面因子状态为 `UNAVAILABLE`，策略按第 9.5 节降级运行。

ETF 不直接套用个股基本面。ETF 使用独立的质量模块，例如规模、成交额、跟踪误差、折溢价、费率以及底层指数或行业的基本面代理。

### 8.3 行业景气度数据

MVP 实际采用免费的 **新浪行业分类**：

- 一级行业用于行业景气评分、行业仓位约束和报告汇总；
- 每日保存行业成分快照和采集日期，逐步形成自有历史；
- 新浪接口不提供可证明的历史生效区间，因此某次采集的行业归属只从采集日开始生效，不回填更早的回测日期；
- 申万 2021 版仍作为后续可替换标准，待获得免费、稳定且带历史生效日期的数据源后另行接入。

MVP 分两层：

1. **结构化量化层**：成分股 20/60 日相对收益、价格相对 60 日均线状态，以及位于 20/60 日均线之上和 20 日收益为正的成分股比例。
2. **资料证据层**：上市公司公告、交易所披露、统计部门、行业协会和公司财报等一手材料的摘要与引用。

若某行业缺少可靠的结构化景气指标，只生成“数据不足”状态和资料证据，不自动给出虚构分数。

### 8.4 资料搜索记录

每条资料至少保存：

```yaml
source_type: exchange_filing
url: "..."
title: "..."
publisher: "..."
published_at: "..."
fetched_at: "..."
entity_ids: ["..."]
claim: "..."
direction: positive | neutral | negative
confidence: 0.0
checksum: "..."
```

资料搜索模块可以做检索、去重、摘要和证据归档。MVP 中，非结构化文本不能直接修改量化得分；它只进入候选证据卡或形成需要人工确认的行业标签。后续若自动量化文本信号，必须另立策略版本并做独立验证。

### 8.5 数据源调研结论与接入顺序

截至 2026-09-28，MVP 采用“行情主源固定、基本面和行业来源可选”的方式：

| 优先级 | 来源 | 拟用范围 | 已确认能力 | 接入前提与限制 |
|---|---|---|---|---|
| 1 | 新浪/AkShare | 境内 ETF、A 股日线行情 | 复用课程阶段已经验证的新浪行情路径 | 仍需保存请求时间、复权口径和质量检查；不得静默切换 |
| 2 | [Tushare Pro](https://tushare.pro/document/2?doc_id=335) | SW2021 分类、历史行业归属，可选基本面 | `index_member_all` 返回申万一至三级行业以及 `in_date`、`out_date`，适合构造时点正确的行业归属 | 需要 Token 和相应积分权限；接入时抽样核验历史覆盖与公告日字段 |
| 3 | [同花顺 iFinD Quant API](https://quantapi.5ifind.cn/gwstatic/static/ds_web/quantapi-web/) | 可选基本面、行业和板块数据 | 官方目录包含基本资料、财务报表、估值、板块成分和行业数据 | 需要有效产品/试用授权；实际字段、历史版本和调用限制须在账号内验证 |
| 4 | [通达信 TdxQuant](https://help.tdx.com.cn/quant/) | A 股基本面 | 已实现本地 HTTP 适配器，按公告日保存专业财务数据 | 需要启动支持 TQ 的通达信客户端并先下载专业财务数据；本机尚未具备该运行环境 |
| 5 | 新浪行业/AkShare | A 股行业分类、行业趋势和宽度 | 免费接口已实现并逐日缓存 | 无历史成分生效区间，只能从首次采集日起积累历史 |

接入顺序为：先完成新浪行情和量价链路；再探测本机已有授权与凭据；通过小样本的字段、日期和覆盖率验收后，才启用某个基本面或行业适配器。网络上只能人工浏览、无法稳定结构化获取的数据只进入证据卡，不进入自动评分。

## 9. 选股策略 v1

### 9.1 分层框架

```text
可交易性硬过滤
  → 量价主评分
  → 基本面质量过滤/评分
  → 行业景气度加减分
  → 同类标的内标准化
  → 候选缓冲区
  → 组合和风险约束
```

ETF 与 A 股分别排名。不同资产类型的原始得分不得直接比较；组合层使用独立的 ETF sleeve 和 A 股 sleeve，再按配置决定两层资金比例。

### 9.2 量价主评分

MVP 候选指标：

| 指标 | 初始定义 | 含义 |
|---|---|---|
| `momentum_20` | `close / close.shift(20) - 1` | 短中期趋势 |
| `momentum_60` | `close / close.shift(60) - 1` | 中期趋势 |
| `ma_structure` | 收盘价、MA20、MA60 的相对位置 | 趋势结构 |
| `volume_ratio_5_20` | `mean(volume,5) / mean(volume,20)` | 放量确认 |
| `price_volume_corr_20` | 收益与成交量变化的 20 日相关性 | 量价同向程度 |
| `breakout_60` | 收盘价相对 60 日最高价的位置 | 突破强度 |
| `realized_vol_20` | 20 日对数收益标准差 | 风险惩罚 |
| `liquidity_20` | 20 日成交额中位数 | 可执行性过滤 |

所有指标使用当日截面的稳健百分位或 winsorized z-score 标准化。默认量价综合权重仅作为初始配置：

```yaml
price_volume_weights:
  momentum_20: 0.25
  momentum_60: 0.25
  ma_structure: 0.10
  volume_ratio_5_20: 0.10
  price_volume_corr_20: 0.10
  breakout_60: 0.10
  inverse_realized_vol_20: 0.10
```

这些权重必须在训练期固定，再进入验证期；不得根据完整样本表现反复调整。

### 9.3 A 股基本面评分

初始建议：

- 盈利质量：ROE、经营现金流/净利润；
- 成长：收入同比、利润同比；
- 财务稳健：资产负债率及异常变化；
- 估值：PE/PB/现金流收益率中可比较的指标；
- 硬过滤：连续重大亏损、审计异常、关键数据过期等。

当前实现对收入增长、扣非利润增长、ROE、经营现金流/净利润和负债率做横截面百分位评分，负债率取反向分位；亏损、非金融企业经营现金流为负、异常审计意见作为硬过滤。金融行业不套用普通企业的经营现金流硬过滤。默认占 A 股综合分的 20%。行业内标准化留作拥有足够行业样本后的下一版改进。

### 9.4 行业景气度评分

行业趋势分为 20 日相对收益分位 30% + 60 日相对收益分位 50% + 相对 60 日均线状态分位 20%。行业宽度为站上 MA20 比例 40% + 站上 MA60 比例 40% + 20 日收益为正比例 20%。最终行业分为趋势分位 60% + 宽度分位 40%，要求至少 10 个成分股且有效覆盖率不低于 80%。行业景气度默认占 A 股综合分的 15%。

### 9.5 综合分

A 股默认：

```text
综合分 = 65% × 量价分 + 20% × 基本面分 + 15% × 行业景气度分
```

ETF 默认使用独立结构：

```text
ETF综合分 = 75% × 量价分 + 15% × 主题/行业景气度分 + 10% × ETF质量分
```

权重均可配置。数据不足时不得自动把缺失项按零分处理；策略配置必须明确是排除、降级为量价模式，还是阻止运行。

MVP 默认采用以下可用性策略：

```yaml
factor_availability:
  required: [price_volume]
  optional: [fundamental, industry_cycle, etf_quality]
  missing_optional_policy: renormalize_available
  no_optional_data_fallback: price_volume_only
```

- 量价数据是生成排名的最低要求，缺失时运行状态为 `BLOCKED`；
- 基本面、行业或 ETF 质量数据缺失时，系统仅在其余可用分项之间按原始相对权重重新归一化；
- 当所有可选分项都不可用时，A 股和 ETF 均退化为 100% 量价评分，运行状态和报告必须标记 `DEGRADED_PRICE_VOLUME_ONLY`；
- 依赖缺失数据的硬过滤规则标记为 `NOT_EVALUATED`，不得声称已经通过；
- 每次运行保存理论权重、实际生效权重、缺失原因和数据源状态，使不同模式的结果不能被混为同一策略口径。

### 9.6 候选缓冲和换手控制

初始默认：

- 新买入：进入同类标的 Top 10；
- 继续持有：未跌出 Top 15；
- 调仓检查：每 10 个交易日；
- 任一硬风险条件触发时允许提前退出；
- 具体数字为配置项，需要通过训练/验证/样本外流程确定。

## 10. 组合与风险控制

### 10.1 组合构建

MVP 支持：

- 等权；
- 分数加权；
- 波动率调整分数加权；
- ETF 和 A 股两个 sleeve 的目标比例；
- 未使用资金保留为现金。

初始配置固定为约 1:1：

```yaml
portfolio:
  sleeves:
    CN_ETF: 0.50
    CN_A_MAIN: 0.50
  unavailable_sleeve_policy: keep_cash
```

两个比例均为配置项。某一 sleeve 没有合格候选时，其额度保留为现金，不自动转给另一 sleeve，避免数据缺失或候选不足时无意放大风险。

### 10.2 交易前风险检查

至少包含：

- 单标的最大权重；
- 单行业最大权重；
- ETF/A 股 sleeve 最大权重；
- 最低现金比例；
- 组合预估波动率；
- 组合集中度；
- 单笔订单金额上限；
- 订单占标的近期成交额比例；
- 当日涨跌停、停牌和不可交易状态；
- A 股 100 股整手和 T+1 可卖数量；
- 数据新鲜度与账户对账状态；
- 组合最大回撤触发的降仓或停止建议。

任何硬限制失败时，订单状态为 `BLOCKED` 并给出原因。

### 10.3 初始风险配置示例

```yaml
risk:
  max_single_stock_weight: 0.08
  max_single_etf_weight: 0.30
  max_industry_weight: 0.25
  min_cash_weight: 0.05
  max_order_pct_of_20d_turnover: 0.01
  max_portfolio_drawdown: 0.15
  lot_size_cn: 100
```

这些是保守的 MVP 起始值，不是投资建议或经验证的最优参数。

## 11. 策略版本和插件接口

```python
class StrategyPlugin:
    strategy_id: str
    version: str

    def build_universe(self, context): ...
    def compute_factors(self, context, universe): ...
    def rank_candidates(self, factors): ...
    def build_target_weights(self, candidates, account): ...
```

策略生命周期：

```text
DRAFT → BACKTESTED → VALIDATED → DRY_RUN → REVIEWED
```

只有 `DRY_RUN` 或 `REVIEWED` 版本可以生成本地订单草稿。任何因子、权重、标的池规则或执行假设变更都会产生新版本。

## 15. 回测与验证要求

### 15.1 防止未来数据泄漏

- Universe 使用当时可见的证券状态；
- 财报按公告日生效；
- 行业资料按发布日期生效；
- 滚动阈值只使用当时之前的数据；
- 当日收盘信号最早按下一可交易时点成交；
- 不允许使用完整样本中位数作为整个历史期间的实时阈值。

### 15.2 成交模型

回测至少包含：

- 下一交易日开盘或其他明确的因果成交价；
- 佣金、印花税、过户费和滑点；
- A 股整手、T+1、涨跌停和停牌；
- 部分成交/无法成交的模拟；
- 现金不足和订单拒绝。

费用口径已于 2026-09-28 确认并配置为 `cn_net_commission_v1`：

- 券商净佣金：成交额的 0.000085（万 0.85），买卖双向，免五，最低佣金为 0；
- A 股证管费：成交额的 0.00002，买卖双向；
- A 股经手费：成交额的 0.0000341，买卖双向；
- A 股过户费：成交额的 0.00001，买卖双向；
- A 股印花税：成交额的 0.0005，仅卖出收取；
- 境内 ETF 经手费：成交额的 0.00004，买卖双向；ETF 不计证管费、A 股过户费和股票印花税；
- 货币 ETF、债券 ETF 的经手费可能享受交易所暂免政策。MVP 尚未可靠识别 ETF 子类型，因此统一按 0.00004 计提，作为保守成本假设；
- 每笔费用合计按人民币分四舍五入。单边不利滑点由 `slippage_bps` 配置：境内 ETF 为 5 bps，A 股主板为 10 bps；买入上调成交价，卖出下调成交价。

费率假设日期、分项费率与佣金下限记录在 `configs/account.yaml`。订单预估、本地模拟成交和研究回测必须调用同一费用组件；运行清单记录费率模型和假设日期。历史研究统一套用该固定费率，因此不表示已还原券商历史费率。

官方交易所费率参考：上交所 A 股经手费与印花税说明 <https://one.sse.com.cn/onething/gptz/>；上交所基金经手费表 <https://www.sse.com.cn/services/tradingservice/charge/ssecharge/c/c_20251231_10803655.shtml>；深交所 2026 年收费表 <https://www.szse.cn/marketServices/deal/payFees/>。

### 15.3 研究分段

所有策略版本需固定：

- 训练期；
- 验证期；
- 不参与调参的样本外期；
- 模拟盘起始日期。

如果已经查看样本外结果，该区间不再被称为未见样本。每次参数修改都重新创建策略版本。

### 15.4 最低报告

- 累计和年化收益；
- 波动率、夏普、最大回撤；
- 年度/月度拆解；
- 换手率和成本侵蚀；
- 行业、标的和因子贡献；
- 不同市场状态下的表现；
- 参数敏感性和 Walk-forward；
- 与简单基准的对比；
- 订单可成交率和容量估计。

## 18. MVP 验收标准

1. 标的池可以通过配置切换境内 ETF、A 股主板或二者组合，境外 ETF 不得进入 MVP 组合。
2. 主板识别基于带日期的证券主数据，并正确排除创业板、科创板、北交所、B 股和配置中的异常状态。
3. 任一历史日期都能生成当时的 Universe 快照，不包含后来上市或当时不可交易的证券。
4. 量价、基本面、行业评分均可追溯到原始输入和公式。
5. A 股财报严格按公告日生效。
6. 资料搜索结果保留来源、发布时间、抓取时间、摘要和校验信息。
7. 非结构化资料不会在未经人工确认和独立验证时直接改变仓位。
8. 同一代码、配置和数据快照产生完全一致的输出。
9. 数据过期、账户不一致或硬风险失败时不生成可执行订单。
10. 订单草稿正确处理 A 股整手、现金、T+1、停牌和涨跌停限制。
11. 回测不使用未来 Universe、未来财报、全样本阈值或当日收盘信号的当日收盘成交。
12. 每次运行均产生完整的 manifest、质量报告、排名、证据、目标权重、风险报告、订单草稿和日报。
13. 本地模拟账户从人民币 500,000 元和空仓状态开始，可以完成假设订单、成交、持仓、现金和绩效对账。
14. 策略修改会产生新版本，旧版本结果仍可重放。
15. ETF 与 A 股 sleeve 默认各占 50%，某一 sleeve 无合格候选时其额度保留为现金。
16. 基本面或行业数据不可用时，报告明确显示降级状态、有效权重和未执行的规则，不以零值代替缺失值。
17. MVP 不包含券商或交易终端适配器，也不存在向外部账户提交订单的路径。
